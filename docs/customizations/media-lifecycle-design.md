# 素材不重复上传、ID 引用与统一数据保留方案

状态：已进入实现阶段。本文记录产品规则和验收标准；代码进度、分阶段 TODO、实际验证结果及上线阻断项集中维护在 [EXT-0045](changes/0045-media-lifecycle.md)。第 2 节保留改造前基线，不能据此判断当前隔离分支或生产部署状态。验收标准不代表已经测试通过。

## 1. 目标

同一素材尽量只上传并保存一份 OSS 文件，多处使用时直接引用，用户可以在输入框粘贴素材 ID。管理员在同一个“数据保留与清理”入口管理 OSS 文件和数据库业务数据：按期限清理（默认 30 天，可修改）、一直保存，以及主动清空业务数据。账号及系统配置保留。

按期限清理时，从最后一次有效使用或编辑起重新计算保留期：再次使用素材会续期，编辑画布、聊天等业务数据也会续期，连续 30 天没有有效活动才进入自动清理。一直保存时不因数据年龄删除。普通用户删除自己的引用不能牵连其他使用者；管理员主动清空不受续期保护。清理主要减少长期存储积累，不承诺降低总流量。

“保留 30 天”现在表示连续 30 天未有效使用或编辑的保留窗口，不限制文件从首次上传起的总年龄。一直有人使用的素材可以保存超过 30 天，甚至长期保留；这是续期的预期结果，不是去重或清理失效。系统仍会产生新数据，定时清理存在延迟和失败重试，保留天数也不是容量上限。

### 适用范围与术语

本文设计本画布服务的云素材去重、分享，以及其 OSS 与数据库业务数据的统一保留，与 [Web 端与本地端产品及素材传输方案](web-local-editions-design.md) 配套。该文档另行规划的 Python 临时素材平台有独立的计费和保留规则，不自动套用本篇续期或清空；共享物理桶时也须按目录隔离。两端运行方式、双 Key 设置及收费边界由配套文档维护，本篇仅确定本画布服务管理范围内的规则。

| 对象 | ID 的作用与可用范围 | 保存与回收责任 |
| --- | --- | --- |
| 云端归档素材 | 云端分享 ID 可用于同账号、跨账号引用；下文未特别注明的“素材 ID”均指此类 ID | 按统一保留模式管理；期限模式下到期清理，一直保存模式下不按年龄删除 |
| 数据库业务数据 | 画布、素材元数据、聊天、历史、任务及引用关系等 | 与 OSS 共用保留模式和天数，账号及系统配置豁免；具体保留与清理清单见第 6 节 |
| 本机素材原件 | 本机 ID 用于本机画布、素材库和去重；仅发送 ID 不能让他人读取本机文件 | 本地端根据持久记录与撤销范围管理，不依赖浏览器缓存作为唯一原件 |
| 临时上传副本 | 临时上传 ID 用于查询和复用托管副本，不自动成为长期分享 ID | 临时服务按任务使用窗口与有效期清理，不删除本机原件 |

本机或临时素材需要长期跨账号引用时，应先完成长期云存储的权限、额度校验、归档和登记，再取得云端分享 ID；不能仅延长临时 URL 或更换 ID 名称。此过程不默认开启本地端的付费 OSS。

现有 `storageKey` 和私有对象 ID 用于存储定位与旧权限读取；本方案新增的云端分享 ID 用于分享授权，不能直接互相替代。

## 3. 已确定的产品方向

### 3.1 云端素材引用由后端登记

画布内容仍允许本地保存，但使用云端素材时，需要让后端掌握引用关系。离线变更本地暂存，联网后补报。设备长期未上线、当前浏览器没有查到素材，都不能单独作为删除依据。

普通删除不能因引用登记不完整或暂时查到零引用误删文件。期限模式下的到期清理及管理员主动清空不以引用是否完整为前提；具体规则见第 6 节。下文“有效期内”包括期限模式下尚未到期，以及一直保存模式下尚未被主动删除的状态。

### 3.2 不设置共享开关，持有素材 ID 即可引用

- 同账号跨画布、跨账号均可通过素材 ID 引用。
- 素材 ID 是分享凭证，任何拿到它的人都可按产品规则查看和添加素材；知道 ID 不等于能够证明双方关系亲近。
- 不自动加入公共素材库，不提供按 ID 枚举或搜索全部素材的入口。
- ID 使用固定可识别前缀和足够强的随机部分，不使用递增编号、内容哈希或 OSS 路径。
- 分享凭证与底层文件标识分离，不直接放开现有对象读取接口的账号校验。
- 用户获得独立引用后，在文件有效期内，原作者删除自己的记录不影响对方；所有引用共同受底层文件到期时间约束。

此前讨论过的“共享开关”“关闭共享”“默认禁止再次分享”均不纳入本版。持有 ID 即可引用的机制允许 ID 被继续转发。

界面提示建议：持有此 ID 的人可查看并引用素材，请勿分享私密素材的 ID。

### 3.3 OSS 与数据库统一保留和清理

- 保留设置只有一个入口，OSS 与数据库业务数据共用模式和天数，不要求管理员分别维护两套周期。
- 按期限清理：默认 30 天，管理员可设置；首次上传/创建开始计时，再次有效使用素材或编辑业务数据后重新计算完整保留期，具体活动口径见第 6.3 节。
- 一直保存：关闭这两类数据按年龄自动清理，不代表禁止用户正常删除或管理员主动清空，也不能恢复此前已经删除的数据。
- 主动清空：管理员可在同一入口清空指定管理范围内现有的 OSS 文件与数据库业务数据，不等待到期；账号登录、权限、余额和系统模型渠道、密钥、OSS 等配置保留。清空是一次操作，不是每天重复运行的保留模式。
- 仅静态存在引用、收藏或历史记录不代表永久保留；有效使用/编辑会续期，长期没有活动的数据仍可到期。管理员主动清空不因活动、引用或撤销而豁免；本机原件不受云端清理影响。
- 不再采用原讨论稿的“零引用后额外保留 7 天”规则。管理员操作、数据库范围和模式切换见第 6 节。

### 3.4 在现有输入框粘贴并识别

不新增专用添加弹窗。素材菜单提供“复制素材 ID”，提示词、聊天等支持参考素材的输入框负责识别。

建议交互：

1. 用户粘贴 ID，输入框发起解析与校验，不自动发送消息或触发生成。
2. 校验并建立当前草稿引用成功后，将 ID 转为参考素材卡片，显示缩略图或类型、名称；仅预览成功不视为添加完成。
3. 混合文字和多个 ID 时，只替换成功解析的 ID，保留文字及失败项。
4. 无效、失效或当前输入框不支持的素材保留原文并提示，不吞掉输入。
5. 同一输入框重复添加同一素材时去重。参考图片、视频、音频合计最多 50 个，不分别设置类型数量上限；所有入口复用同一计数和校验，保留素材类型与实际协议能力校验。单值字段或有限工作流插槽无法承载全部素材时应明确提示，不静默截断。
6. 名称、搜索等普通输入框不启用此识别。

异步结果不能覆盖用户粘贴后继续输入的内容；切换账号或输入目标后，旧请求结果不得添加到新会话。

## 4. 建议的数据关系与保留依据

以下是职责划分，不是已确定的数据库表结构。

| 层级 | 负责的内容 | 关系 |
| --- | --- | --- |
| 文件 | SHA-256、大小、格式、存储位置、原始上传时间、最近有效活动、到期时间、清理状态/版本 | 同一存储范围内相同文件共用一份；续期更新元数据，不复制或重传正文 |
| 用户素材 | 用户归属、名称、素材库保留状态、用于分享的素材 ID | 多个用户素材可以关联同一文件；元数据记录是否存在与是否仍需保留文件分开判断 |
| 使用引用 | 草稿、画布节点、素材库、历史、任务及撤销等使用位置 | 每个位置独立登记和释放；引用归属于使用者，不依赖原作者继续保留素材 |

示例：A、B 分别上传相同图片，共用文件 F。B 再次使用或编辑自己的画布时，B 的画布和当前需要的 F 续期；A 长期未使用的私人画布不因此自动续期。A 的记录删除或到期不会删除 B 仍在有效使用的 F。

### 4.1 建议采用的保留规则

“我的素材”中仍有效的记录应有独立的素材库保留关系，不能只有加入画布才拥有使用关系。下表描述有效期内的引用管理，所有保留关系都受文件到期时间约束，不构成永久存储承诺。

| 使用行为 | 建议建立的保留关系 | 释放条件 |
| --- | --- | --- |
| 上传或主动收藏到“我的素材” | 当前用户的素材库保留关系 | 用户删除个人素材，且相应撤销保护结束 |
| 粘贴 ID 到输入框 | 当前用户、当前草稿的独立引用；不自动加入“我的素材” | 确认移除素材或销毁草稿，且不再受撤销保护 |
| 从草稿提交到消息、画布或生成任务 | 对应持久使用位置的引用 | 该位置删除或任务不再需要素材，且相应历史、撤销保护结束 |
| 生成结果归档 | 对应任务或结果记录的保留关系 | 按结果保留规则明确释放，不因浏览器关闭自动释放 |

已确认粘贴只加入当前草稿，不自动收藏或生成。草稿按账号及输入位置持久化；提交先建立任务或业务引用，再释放被提交的草稿引用。即使复用用户素材元数据，也必须区分“仅被草稿使用”和“已收藏”，避免一次粘贴产生无法释放的素材库保留关系。

例如，B 粘贴 A 的素材到草稿后取得自己的引用并续期。B 提交时先建立任务或作品引用、同步续期，再释放不再需要的草稿引用；仅移除草稿时释放对应关系，不缩短其他使用者的期限。没有引用的文件也按其最后有效活动时间等待清理。

### 4.2 身份与登记约束

建议素材 ID 对应的内容不可变：重命名不换 ID；编辑、裁剪、替换文件后创建新素材，避免远端修改影响已有作品。记录及文件均须符合当前保留策略；任一必需对象被清理后，旧 ID 不再保证可用。

引用登记至少需要区分账号、使用位置类型、位置标识和文件；接口重试不得重复计数，释放同一引用多次不得误减其他引用。更新位置内容时，应保证新引用登记成功后再释放旧引用，不能出现保存成功但引用遗漏的窗口。具体字段、接口和事务边界留到实现设计确定。

云端分享 ID 的停用、某用户引用的释放、物理文件的删除是三个不同动作。作者删除个人素材后停用其旧分享 ID；其他用户已取得的独立引用继续有效，并可复制自己的分享 ID。底层文件最终清理后，所有引用失效。

实现补充：用户“我的素材”集合不是可被整行覆盖的普通配置。服务端返回集合快照版本 `revision`，保存时在生命周期锁内做 CAS；版本冲突必须重新读取并按“加载基线 → 本机当前 → 服务端最新”三方合并。不同素材的新增可以合并，已知素材的删除优先于旧编辑，同一素材同一字段无法安全合并时明确提示冲突并保留本机修改。集合按账号和清理 `epoch` 隔离保存，清理代次或账号切换中的旧响应不得回写。旧无归属本地记录只作为恢复副本，不能自动领取到新账号。

## 5. 同一素材不重复上传与存储去重

目标：同一份文件在相同存储范围内只保存一份 OSS 对象，多处使用、多个账号引用时复用已有文件。当前已支持按账号隔离的上传去重；本方案进一步增加跨账号复用，不能把规划写成已经实现。

| 场景 | 目标行为 |
| --- | --- |
| 已有云素材再次用于画布、聊天或生成 | 校验权限和清理状态，建立引用并续期；不先下载再上传，不新增 OSS 文件 |
| A、B 分别选择内容完全相同的本地文件上传 | 核对内容后复用同一存储范围内可用文件，并为本次使用续期；两个账号各有自己的记录，OSS 只保留一份 |
| 同时上传同一文件或失败后重试 | 保证最终只保留一份有效物理对象和正确的引用关系，不因并发或重试留下重复文件 |
| 修改、裁剪或转码后上传 | 内容已经改变，作为新文件保存；仅文件名不同但内容相同仍可去重 |
| 原文件已到期待清理 | 若尚未锁定删除且对象可用，可按第 6.4 节原子续期并复用，不能仅凭旧索引返回成功 |
| 原文件正在删除或已删除 | 不复用旧对象；明确提示状态，用户重新上传时使用新的有效对象身份，不能被旧删除任务误删 |

实现边界：

- 服务端根据实际文件内容计算 SHA-256，工程上以相同哈希判断相同内容。
- 平台统一存储范围内支持跨账号复用；用户自带 OSS、不同独立存储域不能直接混用。
- 先检查已有对象，再写 OSS；并发上传需要数据库唯一约束和一致性处理，不能仅依赖单进程锁。
- 复用时创建或取得当前用户的素材记录，不暴露其他用户的归属和私有元数据。
- 看起来相同但经过压缩、转码或修改元数据的文件可能具有不同哈希，不做视觉相似去重。
- 上传后的来源索引必须在文件归属、状态和清理代次仍有效时登记；清理确认物理对象不存在后才删除可选来源索引。迟到回调不得凭旧代次重建索引。

这里区分两段传输：已有云素材再次使用时，不重复上传文件；重新选择本地文件时，第一版仍可能将正文传到应用后端校验，但不会再次把相同内容写入 OSS。浏览器只传哈希、完全不上传正文的“秒传”暂不纳入第一版，哈希不能充当访问他人文件的凭证。

## 6. OSS 与数据库共用的数据保留设置

### 6.1 一个入口、两种模式、一个清空操作

管理员在“数据保留与清理”中统一管理，普通用户不能修改全局规则。

| 设置或操作 | OSS 与数据库共同遵循的行为 |
| --- | --- |
| 按期限清理 | 默认 30 天，管理员填写正整数天；素材使用、业务编辑后续期，超过有效保留窗口且无运行中任务保护时自动清理 |
| 一直保存 | 不按年龄自动删除业务数据；OSS 桶生命周期和既有数据库清理任务也必须同步停用或调整，不能只有页面开关改变 |
| 立即清空业务数据 | 清理执行边界内的全部 OSS 内容与数据库业务数据，不等待到期，保留账号及系统配置；完成后仍沿用原保留模式 |

立即清空需要在界面展示管理范围、对象和记录数量、容量、明确保留项，并由管理员二次确认；这是产品操作要求。开发验证只使用隔离数据库和模拟存储，不执行真实数据清空或修改真实存储策略。

### 6.2 保留与清理范围

已确认保留账号及系统配置，其余业务数据纳入规则。以下按数据职责划分，编码前需映射到具体表、字段和对象目录，不能简单按“用户表以外全部删除”实现。

| 数据 | 处理规则 |
| --- | --- |
| 账号登录、身份、权限、余额、额度及维持账户账务一致性所需状态 | 保留；清理历史不能重置余额、导致重复扣费或破坏登录 |
| 系统及账号的必要配置 | 保留模型渠道、访问密钥、OSS 配置、保留设置等；清理后管理员仍能登录配置，用户仍能发起新操作 |
| 画布、节点、素材库、聊天、草稿、生成历史、任务及结果 | 按有效使用/编辑续期和依赖规则保留；无活动且到期后清理，主动清空按确认范围执行 |
| 引用、分享 ID、上传索引、来源归档映射及业务日志 | 与关联业务和文件保持一致并纳入清理，不能只删正文而长期积累明细索引；仍有效的关联不因索引单独变旧被提前破坏 |
| 清理控制与同步防重建状态 | 仅保留恢复失败任务和拒绝旧客户端回写所需的最小控制信息，完成后压缩或清理，不永久保存作品正文和逐条历史副本 |
| OSS 内容 | 清理配置范围内全部对象，含仍被引用、未登记索引的旧对象；专用桶可覆盖全桶，共用桶须明确本应用目录，不越界处理其他业务 |
| 本机原件 | 不被云端清理删除；浏览器同步缓存需识别云端清理结果，不能自动将旧数据传回服务器 |

保留数据库配置不等于保留其引用的 OSS 图片：头像、站点图片等如果位于清理范围，也遵循 OSS 规则；读取失败应有占位显示，不影响登录和系统配置读取。必要的应用程序资源不应依赖会被业务清空的 OSS 目录。

### 6.3 使用、编辑与续期

已确定：素材再次使用要续期，业务数据编辑后也重新计算保留期。统一公式为“最近一次有效活动时间 + 管理员设置的保留天数”。首次上传/创建作为第一次活动；原始创建时间保留用于追溯，不改写它来假装续期。

为便于实现，采用以下活动口径；续期须由有权限的操作触发，并由服务端确认，不能直接使用任意客户端时间或所有数据库 `updated_at` 变化。

| 行为 | 续期范围 |
| --- | --- |
| 新上传、相同文件再次上传并命中去重、粘贴 ID 添加、主动收藏 | 当前用户对应素材/使用记录与物理文件开始计时或续期；首次上传保存正文，复用已有文件只更新引用及期限 |
| 主动打开画布/会话详情、打开素材详情、播放或下载 | 本次明确打开的内容及正常使用必需的依赖续期；列表缩略图、鼠标悬停预取不算主动使用 |
| 编辑画布、发送消息、修改草稿/素材信息并保存成功 | 所属业务整体、当前内容及直接依赖的素材和必要索引一起续期；不只保留数据库记录而让图片先被删 |
| 用户提交生成、真实任务状态推进、结果首次成功归档 | 本次任务和必需输入/结果续期；相同状态轮询、重复回调、失败重试不反复制造新活动 |
| 后台同步、签名刷新、缓存恢复、列表读取、定时扫描、页面空闲心跳 | 不续期；由真实编辑触发的自动保存可以续期，无内容变化的自动保存不续期 |
| 网络重试、旧客户端重放 | 同一操作按幂等标识只登记一次活动；过时版本或已清空范围的请求不续期 |

主动使用命中本地缓存或 OSS/CDN 直连时，也需通过小型活动登记请求通知服务端，不要求再次上传或让文件正文经过后端。签名链接本身不是续期凭证，匿名抓取、爬虫或持有旧链接反复请求不能绕过活动登记与权限。

数据库按业务整体续期：画布包含当前节点与边关系，会话包含当前消息，草稿包含当前输入。增加新消息或编辑节点时，父记录及其必要内容一起保留，不能因父记录创建得早删掉新内容。独立的调用日志、废弃快照和其他历史不跟随每次编辑无限续期。具体表/字段归属需在实现清单中逐项映射。

续期只沿“本次使用的业务内容 → 必需素材及索引”传播，不反向续期所有引用这个文件的旧作品。共享文件的有效期限至少覆盖自身及所有有效使用依赖中最晚的期限；任何账号有效使用都可延长文件寿命，但不会自动延长其他账号的私人画布、聊天和已停用的分享凭证。释放引用不将已承诺的保留期提前缩短。

为避免长任务在执行中丢失输入，提交后对必要引用设有界的执行保护，完成、取消或超过明确的任务期限后释放。轮询不能无限延长该保护；任务期限与归档重试上限需一起确定。此保护不阻止管理员主动清空，清空按第 6.5 节处理任务和结算。

例：图片上传后第 20 天再次被使用，期限从本次使用重新算 30 天，不重传文件；画布创建后第 29 天编辑并保存，画布、当前节点及仍依赖的图片从本次活动起保留 30 天。只在后台每 5 秒同步相同内容，不产生续期。

### 6.4 清理竞争与模式切换

续期与“锁定删除”必须互斥，不能只在扫描候选时检查一次时间：

| 当前状态 | 续期和清理规则 |
| --- | --- |
| 有效 | 有权限的有效活动更新活动时间和生命周期版本；不得被旧活动倒退覆盖 |
| 因闲置到期待清理，尚未锁定删除 | 对象仍可用时，可原子续期并退出候选；旧清理批次发现版本变化后跳过 |
| 已锁定删除，或删除结果不明确 | 不接受成功续期，先完成删除或核对结果；不得先返回保存成功再删除依赖文件 |
| 已删除 | 不能靠续期恢复；用户明确新建/上传使用新身份，不复活旧分享 ID |
| 管理员主动清空范围 | 按确认的批次边界阻止续期、写入和迟到回调，不用自动清理的“活动后退出候选”规则撤销主动清空 |

业务保存、引用登记及依赖续期要作为一致的提交处理；无法在同一事务中完成时，必须先取得可核对的依赖保护再确认完整保存成功。原本已缺失素材的旧作品可保留占位并编辑其他内容，但响应和界面须明确缺失项，不能把这些文件也报告为续期成功。清理锁定需条件校验活动版本、依赖保护和当前配置，不能在核对之后留下可同时续期并删除的窗口。

| 配置变化 | 行为 |
| --- | --- |
| 修改保留天数 | 建议对新旧数据按最近有效活动统一重算，连同依赖一起核对；缩短期限先预览新增候选，不把设置修改当作所有数据的新活动 |
| 切换为一直保存 | 停止未锁定的自动清理，执行中的删除显示真实结果；已删除数据不恢复，用户主动清空仍可用 |
| 一直保存期间 | 继续记录有效活动，以便日后切回期限模式；不生成强制到期倒计时 |
| 切回期限模式 | 按记录的最近有效活动计算，不能退回首次上传/创建时间；缺失活动数据的先核对迁移基线并预览影响 |

动态续期由应用依据活动和依赖统一判定。可续期对象不能继续由“上传满 N 天就删除”的 OSS 桶生命周期清理当前版本，否则数据库续期后文件仍可能被桶删除。历史版本和残留分片可按单独核对的策略管理，不能影响有效当前对象；续期本身不复制、重写 OSS 对象。

### 6.5 OSS 与数据库协同执行

统一设置不代表 OSS 与数据库能在一个事务中同时删除。建议每日扫描最后有效活动、依赖和执行保护均已过期的候选，用可恢复的清理批次记录范围、触发方式、配置版本和对象身份，分别核对文件、业务记录及关联索引的结果；失败项可重试，但每次执行仍需重新核对资格。

| 阶段 | 必须满足的条件 |
| --- | --- |
| 确定候选 | 期限模式按最后有效活动与依赖期限选取，排除运行中的有效任务保护；主动清空按确认范围选取，两者均排除账号及系统配置 |
| 执行前核对 | 原子核对最新配置、活动/依赖版本、对象身份并锁定删除；续期成功的旧候选跳过，不把同路径新文件或清空后新数据当成旧候选 |
| 阻止旧任务回写 | 清空期间暂停受影响写入或以明确批次边界隔离；处理中任务的迟到回调、归档和旧客户端同步不能重建被清理的数据 |
| 分批删除 | 先保留必要的文件定位和失败重试信息，再执行 OSS 与数据库删除；按依赖顺序处理，不先删索引导致孤儿文件无法追踪 |
| 失败与恢复 | 部分失败显示剩余数量、容量和原因；可重试且不重复扣费，不能将部分成功显示成全部清空 |
| 完成核对 | 核对对象不存在、业务记录及冗余关联已移除、账号和配置可用；之后收敛批次明细，仅保留必要状态 |

自动清理候选在锁定删除前可按第 6.4 节续期；已锁定删除、结果不明确或进入主动清空范围的数据不得成功新增引用、编辑或复用。普通用户删除入口仍保护其他使用者，主动清空按其确认范围执行，不被续期取消。

OSS 版本控制可能让普通删除只生成删除标记，历史版本和残留上传分片也需要纳入占用核查。数据库删除记录后，数据库文件不一定立即变小，需要按所用数据库的空间回收机制验证实际占用。日志文件、备份、数据库 WAL 和 CDN 缓存不等于业务表或当前 OSS 对象，应在上线清单中单列其保留策略；不能据业务清理就承诺整台服务器没有超过 30 天的数据。

### 6.6 清理后的界面、离线与旧数据

- 成功续期的画布不能因其必要素材未续期而丢图。旧数据缺失、人工删除或其他已确认清理导致文件不可用时，仍存在的画布显示明确占位；画布、会话本身被实际清理后才从列表移除，不能仅因扫描列为候选就丢弃用户正在编辑的内容。
- 撤销、刷新、旧任务恢复和离线同步都不能自动恢复已清理的云数据。用户明确重新上传或新建时生成新的有效记录，不复活旧分享 ID。
- 现有项目删除标记可防旧数据复活，但不能直接永久保留全部历史标记来满足新方案。需设计最小账号/同步控制状态或时间边界，既拒绝过时回写，也避免业务历史无限积累。
- 期限模式下显示服务端确认后的新到期时间；续期失败显示待同步或失败，不能先宣称已获得新的 30 天。一直保存模式不显示倒计时，提交任务需确认引用续期及执行保护已建立。
- 离线操作只能本地暂存，服务端不会凭空得知活动。联网后在数据仍可续期时校验身份、版本和操作标识，再以服务端确认时间登记；已经锁定删除或清空的数据不接受旧请求复活。未完成补报前，不保证云端续期成功，本机原件和未同步编辑应继续保留并提示处理。
- 旧 OSS 与业务记录也纳入规则，不能因没有活动索引就永久保留，也不能直接按很早的创建时间首轮全删。应核对可证明的最近活动及依赖；缺乏可靠记录时，建议在迁移确认时统一给予一个保留窗口，再记录后续活动。具体迁移基线需先预览确认，不能把 OSS `LastModified` 或签名刷新时间当作用户活动。

上线先观察并核对范围、候选数量、容量和保留项，再按实际部署授权启用。若仍有活动时间不明、依赖未覆盖或执行失败的数据，应明确报告；续期后长于 30 天的活跃数据属于正常保留，不计作清理遗漏。

## 7. 下载链路

### 7.1 已实现的原视频获取路径

最新工作区已加入原视频结果 URL 约定；它是任务响应字段，与创建请求的 Canvas v1 媒体输入格式是两件事。不能因为某模型选择了 Canvas v1，就假定插件一定返回原视频 URL。

账号代理任务的链路为：

1. 画布后端向 NewAPI 查询任务状态，仍使用网关任务 ID。
2. 任务完成且插件返回 `metadata.canvas_video_result.version = 1` 和有效 `url` 时，后端采用该原视频文件地址。
3. 画布后端直接 GET 原文件、读取字节并写入 OSS，不转码；同任务所有者、相同规范化来源 URL 的归档记录可复用。
4. 归档成功后任务返回 `storageKey`，前端解析缓存或 OSS/CDN 签名地址供播放和下载。已有 `storageKey` 时不再次从上游归档。接入新方案后，真实使用需校验对象并按统一规则续期，单纯恢复缓存和后台签名刷新不续期。
5. 归档失败时任务保持 processing、进度 99 并提供归档错误，后台继续重试，不依赖浏览器一直打开。重试能否成功仍受来源 URL 有效期、服务运行和存储可用性影响。

归档与生成分开记录。先持久化上游结果，再归档；自动恢复最多 12 次、最长 6 小时，退避最多 15 分钟，并受任务总计 24 小时的期限约束。次数在网络请求前保存，进程退出不能使次数归零。归档失败保留结果和可定位原因，不重新提交生成。用户主动重试只安排一次额外归档尝试，不重置自动次数或窗口，仍受总计 24 小时限制；期限已过时提示重新上传可用本机原件。实现和验证状态见 EXT-0045。

任务列表须包含保留期内的成功、失败及进行中任务，支持全新浏览器恢复。终态不得被旧轮询覆盖；任务记录按统一策略处理，旧十分钟清理机制不得使“一直保存”失效。列表分页范围和恢复结果需在最终端到端验证中核对。

来源复用目前按账号和规范化 URL 匹配，仅对特定 S3 签名参数做规范化；更换 URL、其他签名参数变化或跨账号均不保证免于再次拉取。此来源复用与第 5 节的文件内容去重不同。

当插件返回的 URL 指向供应商文件源时，文件正文绕过 NewAPI `/videos/{id}/content`。首次归档仍经过画布后端，并消耗其拉取、上传流量；这不是“浏览器直连上游且所有服务器零流量”。实际源站也必须以返回 URL 和网络请求为准。

当前 QIQI 插件已包含该结果字段。其他渠道是否支持需逐一核对，不能扩展为所有 NewAPI 视频均已走此路径。没有原视频结果 URL、必须鉴权的内容仍使用现有内容接口回退。前端还保留直接响应解析和自动同步分支，不能把所有渠道都描述为后台归档。

### 7.2 后续需要统一的下载策略

保留上述原文件获取与归档实现，不将“直接获取原视频”重复列为新功能。后续重点是用户点击下载时的地址解析、缓存复用和代理回退：

| 来源 | 目标策略及当前边界 |
| --- | --- |
| 可用本地缓存 | 直接保存，不重新下载 |
| 已归档 OSS/CDN | 优先浏览器直连签名链接，应用负责校验和签名；现有解析仍有公开地址或应用内容接口回退，不能承诺全部直连 |
| 未归档且可直接访问的上游链接 | 用户下载目标为浏览器直连，受跨域、防盗链限制时回退；当前普通外链经 `getProxyUrl` 仍可能走应用代理，这部分尚待统一 |
| 需要上游密钥的内容接口 | 保留必要鉴权回退，后续优先接入可用的原文件临时链接并复用归档结果 |

画布应用代理与 NewAPI 中转站需分别检查，不能只绕开其中一层就声称整条链路无中转。不得把上游长期密钥交给浏览器。

上游临时链接不作为永久素材地址。归档成功后在文件有效期内复用 OSS，下载流量仍可能产生 OSS/CDN 费用，但避免重复消耗应用和中转带宽。不要为了优化下载无条件再归档一遍已有对象。签名链接的有效期不应超过文件到期时间；到期后无法凭已保存链接保证继续下载，物理删除与 CDN 已缓存副本的失效边界需在真实环境验证。

## 8. 容量统计建议

- 平台实际占用：分别统计 OSS 去重后的文件大小和数据库业务数据占用，另列待清理、失败与待核对量；保留的账号和配置不计入业务清理完成量。
- 用户逻辑容量：同一用户多处引用同一文件只计一次；不同用户各自计算逻辑容量。到期清理后更新对应占用，物理容量仅在确认删除后扣减。
- 上传、导入和跨账号添加采用同一逻辑容量口径；共享文件的物理容量只计一份。
- 首版仅增加容量统计，不新增硬额度、超额拦截或收费规则。到期清理按统一规则执行。

## 9. 改造顺序与范围

### 第一阶段：建立可靠引用

核查画布、素材库、生成历史、助手消息、Skill、任务结果、草稿、撤销历史及离线存储的引用来源；确定扩展数据模型、有效活动、幂等登记与释放规则。输出数据库保留/清理清单、业务整体与直接依赖映射、活动来源和迁移基线。同步、清理定时器和归档恢复要区分真实使用与维护操作。

### 第二阶段：去重与 ID 粘贴

在共享对象删除保护已建立的前提下，实现跨账号去重、素材 ID 解析、独立引用及输入识别，并接入活动续期、到期时间展示及容量统计。复用可续期对象时原子更新关系与期限，拒绝删除中的对象。下载保留缓存与直连能力，活动登记不额外传输文件正文。

### 第三阶段：统一保留设置与协同清理

实现“按期限清理/一直保存”和“立即清空业务数据”的统一入口，OSS 与数据库共享模式和天数；验证有效活动及依赖续期、清理竞争、设置切换、账号配置保留、旧数据迁移和失败重试。移除会按原始上传年龄误删当前对象的桶生命周期规则，再观察候选并按部署授权启用；主动清空和自动清理分别验证。

遵循[定制开发规则](rules.md)：实现集中到前后端扩展目录，定制数据优先使用扩展表，上游只保留必要接入点。具体表名、接口、事务与后台任务机制需在代码核查后确定。

第一版不进行旧 OSS 文件批量合并，不修改现有素材内容，不实现浏览器秒传。旧 ID 和读取方式保持兼容；不得直接把旧私有对象 ID 变成全账号分享凭证。

## 10. 验收标准

以下用于开发验收；到期相关条目在“按期限清理”模式下验证，一直保存及主动清空另列。已确认决策集中在第 11 节，实际测试证据集中在 EXT-0045，文档描述不替代运行测试。

- 两个账号上传相同文件，在同一去重范围内仅新增一份物理对象，各有独立素材记录。
- 同一有权访问且可续期的云素材在多个画布、聊天和任务中再次使用时，登记引用并续期，不重复上传；重新选择相同本地文件允许正文校验，但不增加 OSS 对象。并发上传、重试及改名上传均核对对象数与活动时间。
- 同账号跨画布、跨账号粘贴 ID 可添加参考素材，不自动生成；文字、失败项和用户后续输入不丢失。
- 按建议的“仅当前引用”方案，粘贴不新增素材库保留关系；收藏建立独立保留，移除草稿不影响已提交内容。刷新、断网和切换账号不导致引用误释放或串用。
- 重复登记、释放和网络重试保持幂等；草稿提交及素材替换不出现引用保护空窗。混合参考素材验证 49、50、51 个边界，超过合计 50 个或协议无法承载时明确提示，不静默截断。
- 文件有效期内，删除任一用户的引用不破坏其他账号、画布或有效撤销中的文件；离线、旧客户端和未完成登记的数据不因零引用被提前删除。
- 图片首次上传后第 20 天被再次使用，新的到期时间为本次活动后 30 天，不增加 OSS 写入；再无活动且依赖/任务保护结束后才进入清理。
- 画布创建后第 29 天编辑保存，画布、当前节点和必要素材从该次活动起续期；会话增加新消息也同步保护父记录，不能被旧创建时间删掉。
- B 使用共享文件延长物理文件期限，但 A 未活动的私人画布/聊天不随之续期；清理 A 的记录不破坏 B 的有效引用。
- 后台每 5 秒同步、列表缩略图、自动重签名、同状态任务轮询、失败重试均不续期；真实打开/编辑、播放/下载按第 6.3 节登记。命中缓存或 CDN 时仍能登记活动且不重传文件。
- 管理员调整天数后按最近有效活动和依赖处理新旧数据；一直保存期间也记录活动，切回期限模式不误用原始创建时间。普通用户无权修改全局策略。
- OSS 与数据库使用同一模式和保留天数；业务记录到期后按确定的清理单位移除，账号登录、权限、余额、渠道、密钥和 OSS 等配置仍可正常使用。
- 一直保存模式不按年龄清理 OSS 或数据库业务数据；验证已有桶生命周期和数据库定时器均服从新配置，切回期限模式前能预览旧数据影响。
- 主动清空需要管理员确认范围，清理范围内未到期数据也移除；清空不删除账号/系统配置，也不改变所选保留模式。清空后可以新建和上传，不被旧批次或迟到回调再次删除、复活旧数据。
- 清理覆盖本画布服务管理范围的 OSS 与业务记录，旧数据按经核对的活动/迁移基线处理；不越界清理独立 Python 临时平台或其他业务。当前对象不被固定上传年龄的桶规则提前删除。
- OSS 删除失败可重试，确认成功后才扣减物理容量；观察模式不执行删除。同路径重新上传或修改保留配置，不会被旧清理任务误删。
- 扫描列为候选后发生续期，旧清理任务必须跳过；续期与删除锁竞争最多一方成功。已锁定删除或结果不明时，不得报告保存及依赖续期成功；主动清空不被活动撤销。
- 原有删除接口保护其他用户的有效引用；长任务保护有明确期限，不被查询无限延长。超时、取消及主动清空场景无迟到数据复活或重复扣费。
- 离线编辑在服务端确认前显示未完成续期；已清理内容不被旧版本回写复活，本机原件和待处理编辑保留。仍存在但缺失素材的旧画布有占位，实际删除后的记录从列表移除。
- OSS 或数据库部分清理失败时不能显示全部完成；重试不丢失文件定位信息、不重复扣费。关联索引、业务日志与删除标记不无限积累，必要控制信息不包含历史正文。
- 验证清理时间、剩余闲置到期数量、失败量及实际占用；持续续期的数据允许保存超过 30 天，不显示“所有文件最多存在 30 天”的错误承诺。
- 本地缓存可用时下载不重新请求正文；可用 OSS/CDN 签名地址的正文直连存储。签名或直连失败时验证允许的回退路径，记录应用及 NewAPI 实际参与情况，回退不计作直连成功。
- 插件返回原视频结果 URL 时，验证首次归档直接获取原文件且字节内容保持一致；已有有效 `storageKey` 或命中同所有者、同规范化来源且未过期的归档记录时不重复获取或写入。不同来源 URL 的内容去重另按第 5 节验收，不要求免拉取。未支持结果字段的渠道验证内容接口回退。
- 关闭浏览器后，账号代理任务仍能完成原视频归档；客户端保留任务 ID 且文件未过期时，重开可查询结果并解析 `storageKey`。这是现有路径的回归项；无任务 ID 的完成结果发现能力须按后续选定方案单独验收。
- 归档恢复测试覆盖临时存储故障、来源 URL 失效、服务重启；按确定的重试策略显示可恢复或终止状态，不重新提交生成请求。
- 未到期的老素材仍可读取；新分享机制不绕过旧对象权限，账号切换不会串用素材。
- 本机 ID、临时上传 ID 不能冒充云端分享 ID；临时副本清理不影响本机原件。本地端实现时再验收本机持久化与回收，不把其完成作为 Web 云素材第一版的前提。
