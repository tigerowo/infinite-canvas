状态：交付准备中，未执行生产部署。实际进度与阻断项以 [EXT-0045](changes/0045-media-lifecycle.md) 为准。当前本地验收镜像为 `infinite-canvas:lifecycle-experience-fix-7`（`sha256:5730951c1382330c19899723a06ee9c5a2e56594aa6a84cc388176e7787e3580`），不是最终生产发布镜像。

## 发布前提

完成功能 TODO 和最终三端全链路排查，同一源码通过三数据库、全后端/race、全部前端测试、独立类型检查、Linux 生产构建及浏览器回归。最终镜像 ID 须关联源码 SHA 清单；后续改代码就重新验证并构建。MySQL 目前存在 StorageObject 迁移阻断，未修复及实测前不能用于此版本发布。

确认目标数据库、持久卷、域名、平台/用户存储范围、备份及回退镜像。部署、收费生成与真实云删除分别需要明确授权；以下是操作步骤，不自动执行。

## 镜像与配置

从验收后的工作树构建独立标签，不覆盖阶段镜像或 `latest`：

```sh
docker build -t infinite-canvas:lifecycle-release-candidate .
docker image inspect infinite-canvas:lifecycle-release-candidate --format '{{.Id}}'
docker image save -o lifecycle-release-candidate.tar infinite-canvas:lifecycle-release-candidate
```

配置文件不提交、不打印。固定强随机 `JWT_SECRET`，设置独立管理员密码及实际 `PUBLIC_BASE_URL`。SQLite 使用 `STORAGE_DRIVER=sqlite`、`DATABASE_DSN=/app/data/infinite-canvas.db`；PostgreSQL 使用 `STORAGE_DRIVER=postgres` 和实际 DSN。外部数据库及 `/app/data` 均需持久化。

Next.js 监听 3000，并代理 `/api/*` 到容器内部 Go 8080。外部只暴露 Web 入口；检查 `/app/web/server.js`、`.next/static`、`public`。反向代理需验证 HTTPS、上传体积、超时、Range 和跨域设置。

## 隔离演练

当前环境使用 3104、`lifecycle-web-stage`、独立卷 `lifecycle-stage-data` 和网络 `lifecycle-validation`。禁止替换原 3000 服务或复用生产数据库/桶作为删除夹具。

对最终候选镜像，用隔离数据库和模拟供应商/存储执行：

1. 检查 `/api/health`；实际登录访问画布、生图、视频、素材库、管理员保留页，核对静态资源、API 代理和浏览器异常。
2. 创建无收费测试画布和素材，变更策略并重启；交叉核对页面、API、数据库及对象数。
3. 两个独立浏览器验证编辑/删除/离线恢复；额外账号核对越权、串用与旧请求拒绝。
4. 注入上传后索引失败、归档失败、删除超时、进程重启、重复回调及续期/清理竞争，检查定位、引用和结算。
5. 验证 Web/API 任一进程退出会使容器失败，编排器能重启；记录恢复演练结果。

当前本地验收容器已完成基础健康、页面、策略重启持久化以及本轮工作台浏览器回归。真实账号历史、实际渠道、最终发布镜像完整链路及双进程退出演练尚未完成。

## 生产切换（授权后）

1. 暂停写入，等待上传、请求和清理执行器结束，核对 unknown 结算与待归档任务。不得靠重发生成恢复不明任务。
2. 记录旧镜像 ID、配置和数据库版本，做一致性备份。SQLite 停止写入后保存数据库及 WAL 等关联文件；其他数据库使用一致性备份工具。同时备份用户文件、必要配置和对象版本，先验证可在隔离环境恢复。
3. 用备份副本预演启动迁移。扩展建表可重复，但业务回填/字段迁移有数据副作用；迁移失败停止发布。
4. 固定验收镜像 ID，挂载正确持久卷和环境配置，先启动单实例检查健康及页面，再验证无收费写入。首次保持 `observe`。
5. 恢复流量并核对登录、同步、任务恢复和素材读取；异常按下节回退，不自动重发付费任务。

启用清理是单独管理员操作：核对每个 endpoint/bucket/prefix/owner、旧对象和未索引清单，禁止按首次上传年龄删除当前对象的桶策略破坏续期。缩短期限或启用执行须确认新增到期预览。旧范围和清理缺口未解决时，禁止启用生产清理。历史版本、分片、CDN、WAL、日志、备份须独立核对，不能承诺整台机器只保留 N 天数据。

## 回滚与数据恢复

代码回滚不能恢复已删除 OSS 文件，也不能自动撤销字段迁移、清空代次或结算状态。

- **未删除数据：** 暂停写入、保留当前卷/库副本，先在隔离恢复副本核对旧镜像兼容性，再切回记录的旧镜像 ID。保留扩展表，不执行未经验证的删表脚本。
- **已迁移历史字段：** 旧代码可能看不到迁移后的历史。用发布前一致性备份及之后新增数据制定恢复方案，不能只换镜像就算回退完成。
- **已部分清理或结果不明：** 保留批次、文件定位、epoch、操作和结算记录，由具备生命周期保护的代码恢复失败批次。旧版本缺代次/删除保护时不能直接接回流量。
- **恢复被删除作品：** 同时恢复匹配数据库和对象版本，核对共享引用、防旧请求回放及结算防重。无对象备份时无法用代码恢复文件，应提示重新上传本机原件。

恢复后核对账号余额/权限、系统配置、引用、任务终态、哈希、签名/Range/下载、双浏览器同步和旧请求拒绝。未真实验证的存储及生成能力继续列为未验证。
