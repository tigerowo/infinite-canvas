# 云端模型 Key 策略与提示词库分页计划

## 目标

- 管理员维护云端渠道的接口地址、模型和渠道状态。
- 管理员可选择所有用户统一使用后台 Key，或要求用户按渠道填写自己的 Key。
- 用户 Key 只绑定发布的渠道 ID，不能覆盖管理员的接口地址和模型范围。
- 提示词库使用服务端页码分页，并支持选择每页数量。

## 实际实现

- 在公开模型渠道设置中增加 `apiKeyMode`，默认值为 `admin`。
- 用户 Key 保存在登录用户自己的 `modelConfig.remoteChannelKeys` 中；云端请求仍由后端代理，并由后端将用户 Key 注入上游请求。
- 用户 Key 模式只把渠道名称和管理员配置的 Base URL 作为只读信息展示给用户。
- 将提示词中心和画布提示词选择弹窗从无限滚动改为页码分页，支持 12/20/36/60 等每页数量；第 2 页以后通过独立元数据查询保留筛选项。
- 删除前端提示词无限滚动的运行时依赖和对应测试，保留稳定的分页接口与后端排序。

## 验收标准

- 旧配置没有 `apiKeyMode` 或 `remoteChannelKeys` 时按兼容默认值运行。
- 管理员模式不要求用户填写 Key；用户模式缺 Key 时后端明确拒绝请求。
- 云端请求不能使用用户提交的 Base URL 替换管理员渠道地址。
- 提示词翻页不会重复请求整页，也不会再依赖滚动触底加载。
- TypeScript、Next.js 构建和差异检查通过；具备 Go/Bun 后补跑后端与定向测试。
