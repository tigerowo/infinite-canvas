# 微鑫画布前端玻璃质感与自我迭代计划

## 目标

在最多三轮内完成一次可回退、可验证的前端体验升级：让导航、工作台输入区、画布工具栏和侧边面板形成统一的 Apple 风格玻璃质感，同时改善动画、动效、交互、响应式和可访问性。玻璃效果只用于承载层级和状态，不覆盖画布节点与大面积媒体内容。

成功标准：

- 浅色、深色和 375px/768px/1280px 视口下视觉层级稳定，文字对比度可读。
- 玻璃表面使用统一 token，限制 `backdrop-filter` 的数量和面积，不把模糊加到节点和长列表。
- 主题切换、轮播、批量节点和浮层在 `prefers-reduced-motion: reduce` 下不产生非必要动画。
- 关键图标按钮具备可见焦点、可访问名称和足够触控命中区；导航提供当前页语义。
- 非首屏图片和历史视频降低加载与解码开销，拖拽过程不引入额外的全量重渲染。
- 不重新启用已关闭的首页宣传轮播，不修改 NewAPI、OSS、数据库或既有业务协议。

## 第一性原理

1. 用户首先需要知道“当前在哪里、可以做什么、操作是否成功”，视觉效果必须服务于这三个判断。
2. 玻璃材质的价值来自背景透出、层级分离和状态反馈；过度透明会降低对比度，过度模糊会增加渲染成本，因此只应用于少量浮层和固定面板。
3. 动效只在表达状态变化、空间连续性或操作反馈时存在，并且必须允许用户关闭。
4. 画布节点和媒体是内容本身，应保持清晰、稳定和可预测；性能预算优先留给拖拽、缩放和媒体预览。

## 调查结论

- 当前主题已有中性色和画布主题，但没有玻璃填充、边框、高光、阴影和模糊 token。
- 全局导航、首页 Agent 输入区、画布顶部栏、工具栏、缩放控件和侧栏存在重复的透明背景与阴影写法。
- `ai-title-aurora` 为未使用的无限动画；全局没有统一 reduced-motion 兜底。
- 画布节点的 React memo 被父层内联回调削弱；多选拖拽存在嵌套查找并每帧写入状态的热点。
- 多个移动端按钮小于 44px，部分悬浮操作只在 hover 时显示，自定义全屏预览缺少完整 dialog 语义。
- 图片/视频历史与资源卡片仍有原生媒体加载和长列表开销，需要做低风险的懒加载、预加载和触控修复。

## 实施范围

### 视觉基础

- 在 `globals.css` 增加浅色/深色玻璃 token 和少量 `.glass-surface`、`.glass-surface-strong` 工具类。
- 在 `canvas-theme.ts` 增加画布玻璃面板 token，保留现有需要纯色或十六进制的字段。
- 导航、首页/工作台 composer、画布顶部栏、工具栏和缩放控件接入统一表面。
- 不给 `CanvasNode`、缩略图列表和大量重复卡片增加 backdrop blur。

### 交互与可访问性

- 全局增加 reduced-motion 规则；必要时在主题切换和关键组件中跳过视图过渡。
- 补齐导航 `aria-current`、icon-only 按钮名称、悬浮操作的 `focus-visible` 和触屏可见性。
- 为提示词输入和关键弹层补充 focus 状态；改进画布全屏预览的 dialog 语义和控制按钮标签。
- 统一移动端命中区，不改变图标视觉尺寸。

### 性能与逻辑

- 删除确认未使用的 `.ai-title-aurora` 旧 CSS；保留外部 Banner 数据和组件文件，避免扩大本次范围，后续若确认不再使用再单独删除。
- 将拖拽初始位置查找改为 Map，并尽量把连续交互更新限制在必要状态。
- 非首屏原生图片补充 `loading="lazy"` 和 `decoding="async"`；视频历史默认 `preload="none"`。
- 避免引入新依赖和大范围重构；配置请求合并仅在能用现有结构安全落地时执行。

## 三轮执行方式

### 第 1 轮：基础视觉与低风险交互

建立 token、玻璃表面、焦点状态、触控命中区和 reduced-motion；完成导航、composer、画布工具栏、图片/视频/音频设置浮层的统一视觉；补充提示词摘要与详情入口。

### 第 2 轮：运行时问题与性能

根据类型检查、定向测试、浏览器控制台和性能 trace 修复实际发现的问题；处理拖拽热点、媒体预加载、提示词展示和重复请求中能明确证明的问题。

### 第 3 轮：交叉验收

在浅色/深色与桌面/移动视口检查布局、交互和可读性；运行全量测试、构建、diff 检查、健康接口和未授权接口检查。若没有新的明确问题，提前结束，不强行制造第三轮改动。

## 验证

- `go test ./...`
- 前端 TypeScript 检查、定向 Bun 测试、Next.js 生产构建
- `git diff --check`
- 首页、登录页、提示词页、图片页、视频页和管理员设置页的控制台与网络检查
- 375px、768px、1280px 视口截图和键盘焦点检查
- 桌面与移动性能 trace，关注 LCP、CLS、长任务和媒体请求

## 保留边界

本计划只处理当前项目的前端体验和与之直接相关的性能/可访问性问题。保留工作区现有修改，不拉取、合并、推送或部署远端代码，不自动修改第三方控制台配置。

## 执行记录

- 第 1 轮：完成玻璃 token、导航/输入区/画布 dock 接入、焦点状态和 reduced-motion 规则；移除确认未使用的无限动画 CSS。
- 第 2 轮：完成拖拽初始位置 Map 优化、历史视频延迟预加载、图片懒加载、全屏预览语义和移动端触控区修复。
- 第 3 轮：复核后发现首页提示词展示和画布侧栏仍有直接渲染完整提示词的遗漏，已补齐摘要与详情入口；随后完成桌面/移动 Lighthouse、首页性能 trace、TypeScript、生产构建、前端摘要 smoke test、浏览器控制台检查和 `git diff --check`。本地环境未提供 Go 与 Bun 可执行文件，Go 全量测试和 Bun 定向测试留待具备对应工具的环境执行；登录后的提示词详情及真实媒体生成也未在本轮自动化验证。
- 追加收口轮：根据运行时和交互审查，修复提示词详情动作语义、分页停止条件、按钮默认样式和筛选控件触控尺寸；增加图片/视频生成提交锁、触屏参考素材删除入口、结果操作按钮标签与媒体失败状态；复核首页、图片、视频的 375/768/1280 视口均无横向溢出且控制台无错误。由于用户继续提出视觉和交互优化，本次视为同一前端迭代的收口，不扩展到后端、NewAPI、OSS 或数据库。
