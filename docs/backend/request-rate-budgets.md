# 请求速率与并发预算

后端对容易放大 CPU、内存、带宽或第三方请求成本的入口设置固定时间窗速率限制和同时执行数限制。超限返回 HTTP 429、标准 API 错误结构和 `Retry-After`。

| 操作 | 主体 | 每分钟请求数 | 同时执行数 |
| --- | --- | ---: | ---: |
| 注册、登录、登录码交换及 Linux.do OAuth | 客户端 IP | 20 | 4 |
| AI 生成、画布异步任务、工作流 Agent、本地参数转译 | 登录用户；未登录时为 IP | 60 | 4 |
| 文件及参考媒体上传 | 登录/匿名用户 | 30 | 2 |
| 存储容量统计、Provider 测试、模型探测及提示词同步 | 登录用户 | 30 | 2 |
| 公共图片代理 | 客户端 IP | 60 | 4 |
| 文件、参考媒体和视频内容下载 | 登录用户；公开路由为 IP | 120 | 4 |

此外，每个用户最近 30 分钟内最多保留 8 个处于 `queued`、`in_progress`、`processing` 或 `running` 状态的视频、画布图片和画布音频任务。创建任务前会把数据库活动任务和本进程尚未落库的预留槽位一起计算，避免并发请求同时越过检查。

## 执行规则

- 用户限额以鉴权上下文中的用户 ID 为键；公共或未登录入口使用 Gin 在禁用可信代理后的客户端 IP。
- 速率状态最多保存 10,000 个主体；达到容量时先删除已过期时间窗，仍满则拒绝新主体。
- 并发计数在请求结束时释放，包括处理失败和客户端取消。
- 活动任务查询忽略创建时间超过 30 分钟的遗留运行态记录，与视频任务总体 deadline 保持一致。
- 当前速率和 HTTP 并发计数保存在单个 Go 进程内，重启会清零；SQLite 中的活动任务数量不会因重启清零。多实例部署前需要改为共享限流存储。
